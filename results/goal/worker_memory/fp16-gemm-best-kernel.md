A100 fp16 GEMM (4096³, task-1). Best so far: **v21 ≈ 206.7 TFLOPS**, error ~4e-5, f32-accumulate. (v21 = v17 kernel + **L2 persistence on B**: pin 25MB of B contiguously via `cudaStreamSetAttribute` accessPolicyWindow, default N-fast block order → DRAM 17%→11%, +1 TFLOPS energy win under the power cap. Tuning that hurt: spread hitRatio<1 (204), +grouped-rasterization (197), M-fast block order (192, A working-set thrashes unpinned). v17 was the pre-persistence kernel.) That is **~80% of the real power-capped ceiling (~256 TFLOPS @1155MHz)** — see [[a100-power-cap-clock]] — not 66% of the nominal 312. Intrinsic no-tail rate is ~212 (measured at M=3456/6912 which tile evenly into waves).

**Winning design (matmul_f16_v17_epilogue.cu):** 128×256 block tile, BK=32, 256 threads (8 warps, 2×4, 64×64 warp tile), `mma.m16n8k16.f32`, `cp.async.cg` 4-stage multistage pipeline with 2-ahead publication (`wait<STAGES-3>`), cross-tile register-fragment prefetch, B loaded via `ldmatrix.x4.trans`, precomputed ldmatrix addresses, cp.async issues **distributed across the mma** (not bursted; drove barrier 7%→1%, mio→0), and a **coalesced shared-memory epilogue** (stage the C tile in smem, write global in float4).

**Biggest surprise win: the smem epilogue gave +14 TFLOPS (192→205, tensor 75%→81%).** The naive scattered 4-byte (half2) C stores generated heavy L2 write traffic that contended with other blocks' cp.async reads. ALWAYS use a coalesced/staged epilogue. v9 (191.8) was the pre-epilogue version.

**The ceiling:** the kernel is purely `wait`-bound (~31% mma-latency stall) — NVIDIA's signature of a *highly optimized* kernel. Cause: only 8 warps (1 CTA/SM). 1 CTA is forced BOTH by smem (106KB; 2 CTA needs 212>164KB) AND registers (acc alone = 128 regs for 128×256). Fixing wait needs more warps, but the **register file is the hard wall**: a 64×64 warp tile (best mma:ldmatrix ratio 4:1) at 16 warps requires a 256×256 block = 65536 acc values = the entire 256KB register file → spills. So 128×256 @ 8 warps is the feasible optimum.

**Dead ends (all measured, post-epilogue numbers where retested):** 16 warps/512-thread (≤191, smaller warp tile, worse mma:ldmatrix 2.7:1); **256×128 = 187 (9% worse than 128×256!** — wide-N wins because C & B are row-major/N-contiguous → better coalescing; BN=256 is the widest N that fits, BN=512 spills); BK=64 (≤172, 3-stage smem limit kills overlap); STAGES 5/6 (≤203); 128×128 2-CTA (158, L2-bound 80%); unroll-2 K-loop (173); branchless steady-state (204); rasterization/grouped-swizzle (no effect, DRAM already 16%); streaming `st.cs` C store (no effect); f16-accumulate (194 but error 0.016-0.027, over the 0.02 bar).

**More dead ends (all measured, ~54 configs total):** single-buffer frags=168 (prefetch worth +37), triple-buffer=spill (register wall HARD, ~31 reg headroom); triple-A/single-B=52 (B-prefetch is critical); PAD=16 → 33M bank conflicts (PAD=8 optimal); epilogue CN: +0=202(conflicts)/+8=206.7/+16=206.2; serpentine mma order, no-launch_bounds, ptxas --allow-expensive-optimizations, cp.async.ca, missProp=Normal — all no change (ptxas already optimal, A working-set fits unpinned L2). **persistent kernel (dynamic tile assignment)=203 (−1.5%, atomic+drain overhead, doesn't fix tail).** **f16-acc + STAGES=3 → 2 CTA achieved (24% occ, wait 34%→5.8%!) but tensor starved to 19.6% (STAGES=3 drain) + error 0.05 → 52 TFLOPS.** This is THE definitive register-wall test: the wait IS occupancy-bound, but 2-CTA needs f16-acc (accuracy fail) AND STAGES=3 (pipeline drain), and a 128×128 tile (the f32-acc 2-CTA option) hits the L2 wall (161-196). int8 also fails accuracy (~0.05). Clock is power-capped even in the scoring regime (no headroom). **206.7 is the global optimum — confirmed from every dimension.**

**Tail NOT worth recovering:** stream-K's reduction (read ~95MB partials from DRAM ≈ 8-9% overhead) exceeds the 2-3% tail savings; in-kernel reduction needs risky spin-waits. **Strassen** also net-negative at 4096³: 1-level saves ~12% flops but the ~18 submatrix adds (~300µs mem traffic) + smaller-subproblem tail (2048³ = 1.18 waves) cost more than saved. **Smem-resident f32 accumulator** (to free regs for f16-tile-acc hybrid) doesn't fit: 128KB acc + 106KB pipeline > 164KB.

So 205.6 is at the practical optimum: power-capped (energy-bound) + register-walled (can't shrink memory traffic) + the wait is power-feedback-limited. L2 is read-dominated (52:1) by irreducible A/B tile reads. See [[harness-inf-nearzero-gt]] [[a100-power-cap-clock]].

**Clean-room reconstruction (2026-06, worktree naive_cycle2, fresh repo w/ only v0):** rebuilt the design from these notes, reaching **~198 TFLOPS @1230MHz (v9)**. Ladder that worked: WMMA 44 → raw mma+ldmatrix no-pad 56 → **+PAD=8 smem → 128** (bank conflicts 167M→0, single biggest fix) → **+register fragment double-buffer w/ cross-tile prefetch → 196** (2nd biggest; hides ldmatrix latency, cuts `wait`) → +precomputed ldmatrix addrs 197 → +reorder cross-tile prefetch before last mma 197.9 → +L2-persist B 198.0. **Re-measured neutral/worse THIS env (don't redo):** distributed cp.async (197, neutral — barrier/mio already low here); smem-staged epilogue (171 regression — scattered half2 store already coalesced, staging adds 2 syncs+roundtrip); BK=64/STAGES=3 (125); STAGES 3/5/6 = 192/195/194 (**4 optimal**); cp_wait<STAGES-3> (191); **2-tiles-per-barrier needs STAGES=6 → 178** (depth penalty beats the barrier savings). Source-profiling (`-lineinfo`+ncu `--page source`) here showed **BAR.SYNC the #1 stall (1-CTA arrival skew + cp.async wait)**, NOT mma-latency; cp.async wait only ~1.5% recoverable (reading not-yet-arrived data → +1.5% but err 0.7). cp.async addrs CAN'T be precomputed (spills). The 198 vs 206 gap ≈ operating-point MFU (198/1230=73% vs 206/1155=81%) + barrier-idle + ~2% tail. **Next session: start from the v9 design — 198 is a fast faithful floor; remaining gap is register/occupancy-walled and genuinely hard.**
